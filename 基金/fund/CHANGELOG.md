## v1.0.0 — 2026-11-21

首次提交：`3fb9072` `feat(fund): 新增基金数据爬取子项目`

### 新增

- **数据抓取**
  - 基金列表：`fund.eastmoney.com/js/fundcode_search.js`，解析 JS 赋值语句，得到 28382 只基金（代码/拼音缩写/简称/类型/拼音全称）
  - 历史净值：`api.fund.eastmoney.com/f10/lsjz`，按页翻取，字段为净值日期、单位净值、累计净值、日增长率
- **编码模块**（`fund/encoding.py`）
  - `strip_bom` / `sniff_bom`：处理 UTF-8 BOM
  - `decode_bytes`：按 `utf-8 → gb18030 → gbk → big5` 严格解码，返回实际命中的编码名
  - `looks_mojibake`：乱码粗判，防止乱码被静默写进结果
  - `normalize_text`：NFKC 归一化，统一全角字母、全角空格、零宽字符
- **HTTP 客户端**（`fund/client.py`）
  - 请求间隔 200 ms；失败按 0.5/1/2/4 s 指数退避，4xx 不重试
  - 原始响应缓存到 `cache/fund/`，调试可离线复现
- **存储**（`fund/store.py`）
  - CSV 一律 `utf-8-sig`（Excel 双击不乱码）
  - SQLite 两张表 `fund` / `nav`，`INSERT ... ON CONFLICT` 幂等 upsert
  - 净值 CSV 追加写前先读回，按 `(基金代码, 净值日期)` 去重合并
- **命令行**（`python -m fund`）
  - `list` / `nav` / `sync` / `stats` / `clean`，以及用于排障的 `debug`
  - 公共参数 `--refresh`（忽略缓存）、`--no-cache`（不落盘）、`nav --pages N`
- **测试**：32 个离线用例（编码 12、数据源解析与翻页 11、存储 9），全部用样本或替身客户端，不需要联网
- **文档**：`docs/基金数据爬取.md`（数据口径、编码问题、调试记录）、`data/fund/*_sample.csv`（样例产物）

### 修复（开发过程中发现并解决）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | `json.loads` 报 `Expecting value: line 1 column 1` | 列表 JS 以 `EF BB BF` 开头，首字符是 `\ufeff` | 解析前 `strip_bom` |
| 2 | 基金名、日期变乱码，且**不抛异常** | 净值接口响应头无 `charset`，requests 猜成 ISO-8859-1 | 不用 `resp.text`/`resp.json()`，取 `resp.content` 自行 UTF-8 解码 |
| 3 | 每只基金只抓到 20 条净值 | 接口**忽略** `pageSize`，每页固定 20 条且不返回 `TotalCount`；原停止条件是「本页不满 50 条即结束」，第一页就满足 | 页大小按实测 20 定；停止条件改为「本页不满一页 / 本页为空」 |
| 4 | 反复运行 `nav` 后 CSV 出现重复行 | 追加写没有去重 | 读回已有行，按 `(基金代码, 净值日期)` 合并后再整体重写 |
| 5 | Excel 打开 CSV 中文全是问号 | 无 BOM 的 UTF-8 被 Excel 当 GBK | 统一 `utf-8-sig` 写出 |
| 6 | 编码名一律被报成 `utf-8-sig` | 候选编码表把 `utf-8-sig` 排在 `utf-8` 前，它能解任何合法 UTF-8 | BOM 单独用 `sniff_bom` 判断，无 BOM 时优先 `utf-8`（由 `test_plain_utf8` 发现） |
| 7 | `python -m fund` 报 `No module named fund.__main__` | 缺包入口文件 | 补 `fund/__main__.py` |
| 8 | 测试里 `import fund` 失败 | 未安装成包 | 根 `conftest.py` 把仓库根加入 `sys.path` |

> 第 3 条是本版本最实质的 bug：不修的话每只基金只有约一个月的数据，
> 且表面上「抓取成功」，属于静默丢数据。验证方法与排查记录见
> `docs/基金数据爬取.md` 第五节。

### 变更 / 设计决策

- **字段保留字符串**：净值 `DWJZ`/`LJJZ` 不做 `float()` 转换，避免浮点误差与「—」之类的空值把整行丢掉；需要数值时在下游转换。
- **子项目独立**：`fund/` 自带 `config.py`，不引用根目录 `config.py`，因此不影响原有三国杀项目的运行。
- **完整结果不入库**：`data/fund/fund.db`、全量 CSV 已加入 `.gitignore`，只提交 sample；产物可用 `python -m fund sync` 复现。
- **README 未改动**：顶层 README 是三国杀的课程报告，基金项目的说明单独放 `docs/`。

### 已知限制

- 只覆盖「基金列表 + 历史净值」，没有基金规模、基金经理、费率、持仓。
- 净值默认最多翻 5 页（约 100 个交易日）；更长的历史需 `nav --pages N` 手动指定。
- 接口不返回分页元数据，只能靠「本页条数」判断是否到底；若对方改成变长分页，需重新实测。
- 无增量同步：每次按页重抓，靠缓存与 upsert 去重，不做「只拉上次之后」的游标。
- 无并发：单线程顺序抓取，2.8 万只基金全量抓净值不现实，仅适合按代码批量取。
