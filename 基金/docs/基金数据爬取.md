# 基金数据爬取（`fund/`）

> 从天天基金（东方财富）抓取 **全量基金列表** 与 **基金历史净值**，
> 清洗后输出 CSV / SQLite，并附带一套离线单元测试。
>
> 与仓库里原有的三国杀项目互不影响，是独立的子包，入口 `python -m fund`。

## 一、快速开始

```bash
pip install requests          # 本子项目只用 requests + 标准库

python -m fund debug          # 1. 自检：联网 / 编码 / 缓存 / 数据库
python -m fund list           # 2. 抓全量基金列表（约 2.8 万只）
python -m fund nav 000001     # 3. 抓指定基金的历史净值
python -m fund sync           # 4. 列表 + 默认几只基金，一条龙
python -m fund stats          # 5. 看库里现在有什么
python -m fund clean          # 清空缓存
```

常用参数：`--refresh` 忽略缓存重下，`--no-cache` 完全不落盘，
`nav --pages N` 限制翻页数（每页 20 条）。

## 二、数据源与字段

| 数据 | 地址 | 说明 |
|---|---|---|
| 基金列表 | `fund.eastmoney.com/js/fundcode_search.js` | 约 3.2 MB 的 JS 赋值语句，UTF-8 **带 BOM** |
| 历史净值 | `api.fund.eastmoney.com/f10/lsjz` | JSON，**必须带 Referer**，否则返回空 |

抓取结果（实测，2026-11-21）：

- 基金 **28382** 只；类型最多的四类：指数型-股票 5885、混合型-偏股 5856、债券型-长债 2630、混合型-灵活 2386
- 单只基金净值每页 20 条，默认翻 5 页（约 100 个交易日）

字段口径：

| 输出列 | 接口字段 | 说明 |
|---|---|---|
| 基金代码 | `[0]` | 6 位数字，如 `000001` |
| 拼音缩写 | `[1]` | 大写下划线风格，如 `HXCZHH` |
| 基金简称 | `[2]` | 中文名，可能带 `(前端)` 等渠道后缀，见 `clean_fund_name` |
| 基金类型 | `[3]` | 如「混合型-偏股」 |
| 拼音全称 | `[4]` | 全拼大写 |
| 净值日期 | `FSRQ` | `YYYY-MM-DD` |
| 单位净值 | `DWJZ` | 字符串保留原始精度，避免浮点误差 |
| 累计净值 | `LJJZ` | 同上 |
| 日增长率 | `JZZZL` | 百分数，可能为空字符串 |

## 四、编码问题：这个子项目的重点

天天基金三个接口的编码各不相同，也是最容易出错的地方。

### 1. 基金列表带 BOM

文件开头是 `EF BB BF`，直接 `json.loads` 会报
`Expecting value: line 1 column 1`，因为第一个字符是 `\ufeff`。
→ `encoding.strip_bom` 先去掉再解析。

### 2. 净值接口不声明 charset

响应头里没有 `charset`，`requests` 会按 ISO-8859-1 猜，
中文日期、申购状态就成乱码。而且乱码**不会抛异常**，只会静默写进 CSV。
→ 不使用 `resp.text` / `resp.json()`，而是取 `resp.content` 自己按 UTF-8 解码
（`client.get_json` 就干这件事）。

### 3. 老页面可能是 GBK

→ `encoding.decode_bytes` 按 `utf-8 → gb18030 → gbk → big5` 顺序严格解码，
谁先成功用谁，并返回实际使用的编码名，`debug` 命令会打出来。

> 踩坑记录：候选编码里一开始放了 `utf-8-sig`，它能把任何合法 UTF-8 都解出来，
> 导致编码名一律被误报成 `utf-8-sig`（单元测试 `test_plain_utf8` 抓到了）。
> 现在 BOM 单独用 `sniff_bom` 判断，无 BOM 时优先 `utf-8`。

### 4. Excel 打开中文乱码

CSV 用 `utf-8-sig` 写（带 BOM 的 UTF-8），Excel 双击才不会把「华夏成长混合」
显示成问号。`store.write_csv` 统一走这个编码。

## 五、调试过程中真正修掉的问题

| 现象 | 原因 | 修法 |
|---|---|---|
| `json.loads` 报 `Expecting value` | 列表 JS 带 BOM | `strip_bom` 后再取数组 |
| 基金名/日期乱码 | 响应无 charset，被猜成 latin-1 | 取字节自行 UTF-8 解码 |
| 只抓到 20 条净值 | 接口**忽略** `pageSize`，每页固定 20 条且不返回 `TotalCount`；原停止条件是「不满 50 条就停」，第一页就停了 | 页大小按实测 20 定，停止条件改为「不满一页 / 空页」 |
| 反复跑 `nav` 后 CSV 出现重复行 | 追加写没有去重 | 读回已有内容，按 `(基金代码, 净值日期)` 合并 |
| `python -m fund` 报 `No module named fund.__main__` | 缺 `__main__.py` | 补上 |
| 测试里 `import fund` 失败 | 没有安装成包 | 根目录 `conftest.py` 把仓库根加进 `sys.path` |

翻页那个 bug 的验证方法（也是建议的排查套路）：

```bash
python -c "import requests;r=requests.get('http://api.fund.eastmoney.com/f10/lsjz',params={'fundCode':'000001','pageIndex':1,'pageSize':50},headers={'Referer':'http://fund.eastmoney.com/'});d=r.json()['Data'];print(len(d['LSJZList']), d.get('TotalCount'))"
# 输出 20 None —— pageSize 无效、也没有总数，只能靠「不满一页」判断结束
```

## 六、抓取礼仪与注意事项

- 每次请求间隔 200ms（`config.REQUEST_DELAY`），失败按 0.5s/1s/2s/4s 退避重试；
- 原始响应缓存在 `cache/fund/`（已被 `.gitignore` 忽略），调试时可直接对缓存复现，
  不用反复联网；`python -m fund clean` 或 `--refresh` 可清掉；
- 数据仅用于学习研究，接口属于东方财富，请勿高频抓取或商用。
